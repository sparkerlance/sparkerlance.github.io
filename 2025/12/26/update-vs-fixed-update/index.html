update vs fixed update

Created2025-12-26|Updated2025-12-26
|Post Views:

在 Defold（和大多數遊戲引擎）中，
update() 與 fixed_update() 適合執行不同的功能。
如果把物理寫在錯的地方，
角色的重力與跳躍會受到 FPS 影響，
導致物理行為在不同裝置上不一致。

這篇文章用一個簡單的範例，

說明：

  • 兩者的差異
  • 為什麼「物理一定要放在 fixed_update()」
  • 正確的寫法

update(dt) 是什麼？

特性

  • 每一畫面幀執行一次
  • dt 不固定
  • 受 FPS 影響

適合放什麼？

  • 輸入
  • 動畫
  • UI / 相機

fixed_update(dt) 是什麼？

特性

  • 固定時間步長
  • 與 FPS 無關
  • 物理穩定

適合放什麼？

  • 重力
  • 速度 / 加速度
  • 碰撞

錯誤

正確

update()

fixed_update()

結論

方法 處理內容 需求
update() 輸入、動畫、UI 即時滑順
fixed_update() 重力、速度、碰撞 相同結果 
如果把物理寫在update，
低效能的電腦 角色受 重力更新 的 次數就較 低，
高效能的電腦 角色受 重力更新 的 次數就較 高，
導致相同的平台高度 有的人可以輕鬆跳過去，有的人不可能跳過去。
遊戲開發時需要注意這點，才能帶給玩家一致的遊戲體驗。

總結 : 簡單來說，只要是與物理行為相關，
都應該寫在 fixed_update() 中。
